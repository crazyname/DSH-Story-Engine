# 后续开发计划

## 目标版本

当前基线为 `v0.8.0-beta.1` 测试版。以下任务按顺序推进；前一里程碑未满足验收条件时，不把后一里程碑宣称为完成。

## M1：Dispatch 安装前准备

目标：让私人 Dispatch 包从“需诊断”变为经过人工核对的可新建内容包，但不修改或重新分发原始商业游戏资源。

- 生成 `ui/story-ui.json`，使用稳定人物 ID 和中文英雄名/本名。
- 定义私聊、群聊、现场、工作、系统频道及成员。
- 核对第一至第八集过程、玩家选择、人物关系、死亡和具体结局。
- 明确当前恋爱对象为“无人”，未验证字段保持未知，不自动推断。
- 定义首次启动时由 AI 叙写的通关后续作起点。
- 通过 `schemas/story-ui.schema.json`、内容包校验和人工清单。

验收：游戏库显示“可用”；新建存档的人物、频道和连续性与私人资料一致；不得出现示例包人物或错误恋爱对象；3080 完成新建、对话、选择、刷新恢复、另存为、删除和继续游戏闭环。

## M2：完成阶段 C

目标：使 AI 桥接在长回合、取消、失败、刷新和跨存档切换时具备明确且可恢复的状态。

- 为 queued/running/waiting-choice/completed/failed/cancelled 定义回合状态机。
- 增加用户取消和安全重试；重试不得重复提交已完成的正史消息。
- 区分流式临时预览与已提交消息，刷新后只恢复可验证状态。
- 明确删除存档时隐藏 DSH 会话与 Runtime 的保留、回收或孤儿诊断策略。
- 为所有宿主接口增加契约测试和错误码矩阵。

验收：模拟断网、刷新、模型超时、选择等待、切换存档和重复点击均不串档、不丢正史、不重复消息；测试和生产构建全部通过。

## M3：完成阶段 D

目标：把 v0.7 连载后端完整呈现在独立游戏界面中。

- 季、集、场景和频道联动。
- 工作内小事件按“事件名 + 派遣英雄 + 简要结果”输出，不展开为完整任务模拟。
- 工作外主线使用详细场景与分支，支持既有内容发展、反转和新内容。
- 玩家超出预写范围时暂停、修订剧本、校验后恢复。
- 每集结束显示已选择与未选择的关键节点，不伪造联网玩家比例。

验收：至少用原创示例包完成一整集，从开场、工作事件、工作外剧情、选择、越界修订到集末总结，刷新与另存为后连续性一致。

## M4：阶段 E 与发布候选版

目标：形成可公开发布的通用文字游戏插件，不包含私人 Dispatch 内容。

- 键盘导航、焦点、屏幕阅读器、窄屏和高缩放验证。
- 长历史分页、性能和存档 Schema 迁移测试。
- 内容包封面、可选主题、存档重命名和导出/导入策略。
- 第三方许可证、隐私边界、安全审计和公开示例检查。
- 编写安装、升级、卸载、故障排查和内容包作者教程。

验收：发布清单全部通过；公开产物不包含 `packs/private`、运行存档、API Key、商业游戏文本或提取资源；普通 DSH 聊天在插件故障时仍可用。

## 每轮开发的统一完成条件

1. 修改实现与相应测试。
2. 同步 `CURRENT_STATUS.md` 和相关契约文档。
3. 运行核心与客户端类型检查、测试和生产构建。
4. 涉及界面时执行真实浏览器验收，并记录断言结果。
5. 确认 `D:\DeepSeek-Harness` 工作树干净。
